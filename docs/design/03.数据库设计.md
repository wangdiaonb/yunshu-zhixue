## 2. 全局设计规范（database-rules.md 落实）

| 规则 | 本设计落实 |
|---|---|
| 库名/字符集 | 数据库名 `yszx`，字符集 `utf8mb4` + 排序规则 `utf8mb4_0900_ai_ci`（MySQL 8 默认） |
| 命名 | 表/字段一律 snake_case 小写+下划线；业务含义明确，无拼音缩写 |
| 主键 | 统一 `id BIGINT UNSIGNED AUTO_INCREMENT`，唯一非空稳定 |
| 外键 | **全部禁用物理 FOREIGN KEY**；表间用 `<实体>_id` 逻辑关联字段，关联校验/删除保护在应用层（service 事务内）完成 |
| 唯一约束 | 业务唯一值均建 `uk_` 唯一约束：mobile、student.email、subject.name、stage(subject_id,name)、course.bvid、course_subject、question_option(question_id,option_key)、route_course、completion(student_id,route_course_id)、wrong_question(student_id,question_id)、admin_user.username/mobile、role.code、permission.code、role_permission、interview_report.record、student_oauth(provider,open_id)/(student_id,provider) 等（`student.email` 允许为 NULL，MySQL 唯一索引允许多行 NULL，故「可留空 + 非空值唯一」由 `uk_student_email` 直接保障；阶段 4 决议 Q11） |
| 时间 | `DATETIME` 统一 **UTC 存储**，展示层转 Asia/Shanghai；`created_at`/`updated_at` 自动维护 |
| 状态字段 | 取值有限且文档化（见 §4 各表 COMMENT 与 §5 枚举汇总） |
| 必填 | 业务必填字段 `NOT NULL`，默认值有业务含义（如 question.status 默认 3 待审核、gender 默认 0 保密） |
| 金额/分数 | 分数用定点数 `DECIMAL(3,1)` |
| 逻辑删除 | 全站业务表 `delete_flag TINYINT NOT NULL DEFAULT 0`，MyBatis-Plus 逻辑删除插件，查询默认过滤（例外见 §6） |
| 乐观锁 | 需并发控制的表带 `version INT NOT NULL DEFAULT 0`（`wrong_question`、`interview_record`），MyBatis-Plus `@Version`，冲突返回 10004（评审 R-01 裁决，同步 04 §2.13） |

## 3. 核心实体与关系

```
┌──────────────┐      1:n        ┌──────────┐      1:n        ┌───────────┐
│  subject 学科 │──subject_id──→│  stage 阶段 │──stage_id──→│  question 题目 │
└──────────────┘                └──────────┘               └─────┬─────┘
       │ ▲ 方向=学科                    1:n             ┌─────────┘
       │ │ ──subject_id──→ interview_question 面试题     │ practice_record 作答明细
       │ │   （供 AI 面试出题）                          │ （n:1 学员）
       │ │
       │ ├─1:n─→ course 课程（主学科 subject_id，NULL=其他学科）
       │ └─n:m─→ course_subject 课程-学科关联（额外学科）
       │
       │ 1:n ──→ learning_route 学习路线（单学科）
       │            └─n:m──route_course──→ course（顺序=学习顺序）
       │                     └─1:n──route_course_completion（学员勾选完成）
       │
student 学员 ──practice_record / wrong_question / interview_record / route_course_completion
           └─1:n──→ student_oauth 第三方账号绑定（微信 / QQ / GitHub，每平台至多 1 条）

interview_record 面试记录 1:n interview_question_score 逐题评分（含题干快照→回放）
                     └─1:1 interview_report 面试报告

admin_user 后台用户 n:1 role 角色 n:m permission 权限（role_permission 关联）
operation_log 操作日志（审计，无 delete_flag）
```

**关键业务关系规则：**

1. 学科 ↔ 阶段 ↔ 题目：一级挂载链；阶段禁用/学科删除影响学员端可见性（应用层校验，删除学科前需确认无阶段/题目，见需求 4.3.1 三种删除提示）。
2. 学科（方向）= 面试题归属维度（A2）；AI 面试方向复用学科体系（A3）。
3. 课程-学科：`course.subject_id` 主学科（可空=「其他学科」）+ `course_subject` 多学科；「其他学科」不计入关联学科数（统计在应用层排除 `subject_id IS NULL` 与关联表）。
4. 学习路线：单学科（01 文档已确认），跨学科课程通过路线选课的「其他学科课程」分组引入，落 `route_course`。
5. 刷题作答明细 `practice_record` 为学习统计/题目答题统计/错题本的事实来源（02 文档 2.5「明细流水为事实来源，查询时聚合」），`question` 不冗余存答题次数。
6. 错题本每人每题一行，答对纠正计数，连续答对 3 次自动「已掌握」；错误等级由 `error_count` 推导（≥3 高频 / =2 多次 / <2 偶尔），不落等级字段。
7. 面试会话仅已完成落库（D16），未完成会话仅前端本地；逐题评分与报告落库，题干快照支撑回放不受原题修改影响。
8. 后台用户单角色（需求 4.5.1 下拉单选），`admin_user.role_id` 单值；超级管理员内置唯一，`is_builtin=1` 且不可删除/不可改角色。

## 4. 表结构明细（24 张）

### 4.1 学员端账号（auth / student）

#### student 学员表

| 字段 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK 自增 | 主键 |
| mobile | VARCHAR(11) | NOT NULL, UNIQUE | 手机号（11 位），登录账号 |
| password_hash | VARCHAR(100) | NOT NULL | BCrypt 哈希 |
| nickname | VARCHAR(50) | NOT NULL | 用户名（个人中心可编辑，注册时应用层赋默认值） |
| avatar | VARCHAR(500) | NULL | 头像 URL（MinIO） |
| email | VARCHAR(100) | NULL | 邮箱（`uk_student_email` 唯一，允许多行 NULL） |
| gender | TINYINT | NOT NULL DEFAULT 0 | 0 保密 / 1 男 / 2 女 |
| preferred_subject_id | BIGINT UNSIGNED | NULL | 技术方向 → subject.id（D3-4） |
| guide_finished | TINYINT | NOT NULL DEFAULT 0 | 新手引导是否看过（D3-4） |
| status | TINYINT | NOT NULL DEFAULT 1 | 1 已启用 / 0 已禁用 |
| last_login_at | DATETIME | NULL | 最后登录（UTC） |
| created_at / updated_at | DATETIME | NOT NULL | 自动维护（UTC） |

索引：`uk_student_mobile`；`idx_student_created_at`（看板用户增长趋势）；`idx_student_status`。

#### student_oauth 学员第三方账号绑定表（R-03 新增）

| 字段 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK 自增 | 主键 |
| student_id | BIGINT UNSIGNED | NOT NULL | → student.id |
| provider | TINYINT | NOT NULL | 第三方平台：1 微信 / 2 QQ / 3 GitHub |

| created_at / updated_at / delete_flag | — | 同上 | 同上 |

索引：`uk_student_oauth_openid(provider,open_id)`（一个第三方账号只能绑一个学员）；`uk_student_oauth_student(student_id,provider)`（一个学员每个平台至多一条，同时支撑「我的绑定」查询）。
第三方 `access_token` / `refresh_token` **不落库**（仅当次授权流程内使用），授权 `state` 与待绑定票据 `ticket` 存 Redis（TTL 10 分钟）。

## 6. 数据删除策略

**统一原则**（需求文档 §6「删除语义：均为逻辑删除」+ 02 文档 2.5「全站统一逻辑删除」）：

- 全部业务表带 `delete_flag`，MyBatis-Plus 逻辑删除插件，查询默认过滤已删除数据；删除后可恢复。
- 逻辑删除**不级联物理清理**子表数据（子表同标记或随父表逻辑删除后由查询过滤），保证「删除后数据保留可恢复」。

**例外（经 D3-3 / D3-5 确认）：**

| 表 | 例外策略 | 理由 |
|---|---|---|
| operation_log | 无 delete_flag；「清空日志」物理删除；日常行级不逻辑删除 | 审计日志无恢复业务价值，避免大表被 delete_flag 污染 |
| role_permission | 无 delete_flag；编辑权限保存=物理删旧+插新（全量覆盖） | 纯关联数据，覆盖式授权，无恢复业务价值 |

**删除保护（应用层校验，需求已定义）：**

- 学科删除：分三种情况提示（下有阶段与题目 / 仅有阶段 / 无阶段），有下级的先处理下级；阶段删除提示关联题目数（需求 4.3.1）。
- 角色删除：角色下有用户时禁用删除并提示（需求 4.5.2）。
- 面试题删除：按来源给出不同风险提示（手工录入无源文档，删除后不可恢复，需求 4.3.4）。
- 内置超级管理员账号不可删除、不可改角色（需求 4.5.1）。
- 学员删除（后台批量/行删除）：逻辑删除学员，其练习/面试明细数据保留（统计查询默认过滤已删学员）。
