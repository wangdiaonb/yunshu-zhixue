## 1. 项目概述与角色

**定位**：AI 赋能的智能面试训练平台，面向求职者，以「刷题 + AI 面试模拟 + 报告补强」为核心训练闭环。

**平台构成**：

| 端 | 说明 | 主要页面 |
|---|---|---|
| 学员端（Portal） | 独立部署，面向学员/游客 | 首页、题库中心、刷题练习、错题本、学习路线、AI 面试（配置/进行中/报告/记录）、个人中心、注册登录 |
| 管理端（Admin） | 独立部署，面向运营/管理员 | 数据看板、学科管理、B站课程库、题库管理、面试题库管理、学习路线管理、学员管理、用户管理、角色管理、操作日志、系统设置 |

**角色**（需求文档 1.2）：

| 角色 | 归属端 | 主要权限 |
|---|---|---|
| 游客 | 学员端 | 浏览首页、注册、登录、找回密码 |
| 学员 | 学员端 | 训练闭环全部功能（题库/刷题/错题/路线/AI面试/个人中心） |
| 超级管理员 | 管理端 | 全部管理功能（含学员、用户、角色、系统设置） |
| 内容审核 | 管理端 | 内容相关：学科、课程、题库审核、面试题库、学习路线 |
| 运营人员 | 管理端 | 运营相关：看板、学员管理、部分内容（按权限树 9 组授权） |

**核心闭环**：学科/阶段 → 题库/课程 → 刷题练习 → 错题归集 → AI 面试 → 面试报告 → 报告驱动的补强建议（推荐题目 / 推荐课程 / 再次面试）。

### 2.3 关键枚举与阈值（已确认，纳入梳理）

- 题目类型：单选 / 多选 / 判断 / 简答
- 题目难度：简单 / 中等 / 困难
- 题目状态：已上架 / 已下架 / 待审核 / 草稿（DB 预留值，当前不启用）/ 已驳回
- AI 面试题量：3 / 5 / 8 / 10 / 15（默认 10）；单问回答超时：固定 5 分钟
- 错题等级：高频易错（错误 ≥3 次）/ 多次错误（=2 次）/ 偶尔错误（=1 次）
- 错题掌握判定：连续答对 3 次 → 已掌握
- AI 简答批改通过阈值：≥6/10 分
- 找回密码验证码倒计时：60 秒
- 删除语义：逻辑删除（软删除）

## 4. 模块关系与核心业务流程

### 4.1 内容体系关系

```
学科 ─┬─ 阶段（一对多）────────→ 题目（挂在阶段下，供题库中心/刷题练习消费）
     │
     └─（方向 = 学科）─────────→ 面试题（按方向归属，供 AI 面试出题）✅ 已确认
B站课程库（独立维护）──多对多──→ 学习路线（引用课程，课程顺序=学习顺序）
学科/阶段 + 已上架题目 + 课程 ──→ 学习路线可引用（路线构成待确认）
```

- 学科 → 阶段：一对多，阶段是题目的挂载层级，也是首页「热门阶段」的来源。
- 学科 → 课程：**多对多**（✅ 已确认），一课可属多学科，供跨学科筛选与统计。
- 学科（方向）→ 面试题：面试题按「方向（=学科）」归属，来源记录文档名文本，无独立知识库实体（✅ 已确认）。
- 课程库：独立维护（bvid 唯一），可被多条学习路线引用。
- 学习路线：引用课程库课程，顺序即学习顺序；路线归属**单学科**（✅ 已确认）；课程选择器保留「其他学科课程（跨学科补充）」（✅ 已确认）。

### 4.2 核心业务流程

**流程一：内容生产与上架流（管理端）**

```
创建学科/阶段 → 录入课程（课程库）/ 录入题目（新增后直入「待审核」；status=4 草稿为 DB 预留值，当前不启用）
    → 题目提交审核（待审核）→ 审核通过（已上架）/ 驳回（已驳回 status=5，可修改后重新提交→回到待审核）
    → 上架题目被学员端消费；下架后学员端不再展示
面试题：上传 Markdown 文档解析 / 手工录入 / 手动导入 → 主题维护 → 上架供 AI 面试出题
学习路线：选择学科 + 课程（排序）→ 发布 → 学员端展示
```

**流程二：学习训练闭环（学员端）**

```
选择学科/阶段 → 刷题（顺序/随机；客观题即时判分，简答走 AI 批改）
    → 答错自动归集错题本（按次数自动分级）
    → 错题重做（连续答对 3 次 → 已掌握）
    → 学习路线：查看课程顺序 → 跳转 B 站学习（外部）→ 手动勾选课程「已完成」→ 计入已学课程
```

**流程三：AI 面试闭环（学员端）**

```
配置（方向/难度/题量，校验今日剩余次数）→ 面试进行中
    （AI 读题 + 语音识别作答 / 文字作答，每题 5 分钟超时）
    → 逐题 AI 评分 + 整体评价 + 能力分析 → 面试报告
    → 报告留存为面试记录；报告给出补强建议（推荐题目 / 推荐课程 / 再次面试）
```

**流程四：运营管理闭环（管理端）**

```
数据看板监控指标 → 学员管理（详情/禁用）→ 系统管理（用户/角色/权限/设置）
    → 操作日志全程审计
```

### 4.3 模块依赖关系要点

1. **内容管理是学员端数据源**：学习训练消费「已上架题目」，AI 面试消费「面试题库」，路线消费「课程库」；内容管理任何状态变更直接影响学员端可见性。
2. **错题本是学习训练的枢纽**：刷题产出错题，错题重做回灌练习数据，掌握状态反馈学习统计。
3. **AI 面试报告反向驱动学习**：报告补强建议引导学员回到题库/路线/再次面试，形成「练→面→补」循环。
4. **认证与权限横切两端**：管理端权限树决定菜单与操作可见性；学员端独立登录态。
5. **数据统计聚合**：门户首页、个人中心、管理看板、学员详情消费同一批学习/面试统计数据。
