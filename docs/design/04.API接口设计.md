## 2. 全局约定

### 2.1 路径分区（D20）

| 端 | 前缀 | 认证 | 说明 |
|---|---|---|---|
| 学员端 | `/api/portal/v1/**` | 学员 JWT | 门户站（`/`）同域调用 |
| 管理端 | `/api/admin/v1/**` | 管理端 JWT | 后台站（`/admin`）同域调用 |
| 静态/文件 | `/files/**`（MinIO 直链） | — | 头像、Logo 等公开资源 |

- **本文第 4、5 章的接口路径均为省略端前缀的相对路径**（学员端示例：`POST /api/portal/v1/auth/register`；管理端示例：`POST /api/admin/v1/questions`）。
- 前后端分离、同域部署；后端按前缀分区拦截，两端 JWT 完全独立（02 D12），互不通用。
- 契约唯一来源：springdoc-openapi 生成 OpenAPI 3 文档 + openapi-typescript 生成前端类型（02 D21），本文档定义业务语义，二者保持一致。

### 2.2 认证与会话

- 双端独立 JWT：访问令牌 `accessToken`（TTL 2h）+ 刷新令牌 `refreshToken`（TTL 14d，滚动续期）。
- 令牌放置：`Authorization: Bearer <accessToken>` 请求头；刷新/登出接口同时携带 `X-Refresh-Token` 请求头。**任何令牌与敏感信息不得放入 URL 查询参数**（api-rules）。
- 登出与令牌替换：`accessToken` 的 `jti` 写入 `token:blacklist:{jti}`（TTL 至令牌过期）；刷新时旧 `refreshToken` 立即失效。
- 令牌携带用户身份与端标识（`aud: portal|admin`），服务端按端校验；管理端接口额外做 RBAC 权限校验（见 2.8）。
- 「记住我」：登录页勾选项仅为**前端存储策略**（勾选存 `localStorage`、未勾选存 `sessionStorage`），不改变令牌契约；`refreshToken` TTL 仍为 14 天滚动续期（评审 R-04 裁决，接口不增 `rememberMe` 参数）。
- 第三方登录（微信/QQ/GitHub）：OAuth2 授权码流程，`state` 与待绑定 `ticket` 均为一次性、存 Redis（TTL 10min）；第三方 `access_token` 用完即弃、不落库；绑定关系落 `student_oauth`（R-03 裁决）。

### 2.3 统一响应结构（D4-1，方案 A）

成功（HTTP 2xx）：

```json
{ "code": 0, "message": "ok", "data": { } }
```

失败（真实 HTTP 状态码）：

```json
{ "code": 20001, "message": "手机号已注册", "data": null, "fieldErrors": null }
```

- `fieldErrors`：参数校验失败（10000）时返回 `[{ "field": "mobile", "reason": "手机号格式不正确" }]`；其余错误为 `null`。
- `fileErrors`：**批量导入专用**（业务码 30005），返回行级错误 `[{ "row": 12, "field": "正确答案", "reason": "单选题正确答案必须为 A~D 之一" }]`；非导入接口不返回。
- HTTP 状态码与业务码一致，绝不出现「HTTP 200 + 业务失败」或「HTTP 500 + 业务成功」（api-rules）。

### 2.4 分页约定

- 分页参数：`page`（从 1 起，默认 1）、`pageSize`（默认 10，最大 100）。
- 分页响应：`data = { "list": [...], "total": 100, "page": 1, "pageSize": 10 }`。
- 筛选条件变更后前端将 `page` 重置为 1（需求 §6 通用交互约定）。

### 2.5 业务错误码

5 位数字，首位标识归属：1 通用、2 学员端、3 管理端。详见附录 B。

### 2.6 参数校验

- 服务端对所有客户端输入做全量校验（api-rules），采用 Jakarta Validation（Bean Validation 注解 + 分组）。
- 校验失败返回 HTTP 400 + 业务码 10000 + `fieldErrors`（字段名 + 原因），一次返回全部校验错误。
- 手机号正则 `^1[3-9]\d{9}$`；密码 **6~20 位**（需求 §3.2；服务端仅校长度，强度提示由前端展示）；枚举值校验（难度/题型/状态等均来自 03 §5 枚举）。

### 2.7 异常处理

- 全局 `@RestControllerAdvice` 统一映射：业务异常（自定义 BizException）→ 对应 HTTP 状态码与业务码；校验异常 → 10000；JSON 解析失败 → 10007；未捕获异常 → 10006。
- 错误信息面向用户可读，**不返回堆栈、SQL、内部主机信息**（api-rules）。

### 2.8 权限校验（RBAC）

- 管理端接口使用 `@RequirePermission("subject:edit")` 注解，切面按当前管理员角色查权限码集合校验；无权限返回 403 + 10002。
- 权限码与数据库 permission 表一一对应（附录 A，D4-5 定稿共 9 组 34 项）。
- 角色管理 5 个接口不设权限码，仅校验 `role.code = SUPER_ADMIN`（D4-5）。
- 学员端接口校验学员账号状态（禁用返回 20005）与登录态（未登录 401 + 10001）。

### 2.9 SSE 约定（AI 批改 / 面试评分）

- 采用 `POST` 发起 + `text/event-stream` 流式返回（fetch + ReadableStream 消费；EventSource 仅支持 GET，不适用）。请求仍携带 `Authorization` 头，认证失败时正常返回 JSON。
- 响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`；网关需关闭 `proxy_buffering`。
- 事件帧（`data:` 为 JSON）：

| 事件 | 含义 | 负载示例 |
|---|---|---|
| `status` | 阶段推进 | `{ "phase": "analyzing" \| "grading" \| "thinking" }` |
| `token` | 流式增量文本 | `{ "delta": "..." }`（客户端自行拼接） |
| `grade` | 单题评分完成（终止事件，收到后服务端关闭流） | `{ "order": 1, "score": 8, "feedback": "...", "degraded": false, "referencePoints": [...] }` |
| `error` | 中途业务错误后关闭流 | `{ "code": 20010, "message": "..." }` |

- 心跳：服务端每 15s 发送注释行 `: keep-alive`。
- 面试评分：`POST .../sessions/{id}/answers` 每题调用一次，`grade` 事件返回该题评分并写 Redis 暂存（D4-4）。

### 2.10 文件上传（MinIO）

- `POST .../files/avatar`（学员端，P-M05 头像）、`POST .../files/image`（管理端，A-F01 Logo/封面）采用 `multipart/form-data`，字段名 `file`。
- 限制：图片 JPG/PNG；头像 200×200（服务端校验尺寸并等比裁剪，超出报 10008）；Logo 256×256。
- 上传成功返回直链 `{ "url": "/files/xxx.png" }`；文件名由服务端生成（UUID），不做用户可控路径。

### 2.11 时区

- 服务端统一 UTC 存储（`datetime`），接口进出参数按 `Asia/Shanghai`（+08:00）展示。
- 「今日」「每日上限」「日界」均以 Asia/Shanghai 0 点为界（02 D17）。

### 2.12 限流与防刷（D18）

| 场景 | Redis Key | 规则 |
|---|---|---|
| 验证码发送冷却 | `sms:cooldown:{mobile}` | 60s 内 1 次 |
| 验证码每日上限 | `sms:daycount:{mobile}` | 每日 ≤ 10 次，上海日界重置 |
| 登录失败锁定 | `login:fail:{account}` | 连续 5 次密码错误锁 5 分钟 |
| 面试每日配额 | `interview:quota:{studentId}:{yyyymmdd}` | 每日 5 次，TTL 至上海次日 0 点 |
| 通用接口频控 | `rate:{api}:{ip\|account}` | 敏感接口限流，超限 429 + 10005 |
| 验证码校验 | — | 连续校验失败 5 次该验证码失效 |

### 2.13 幂等与并发

- 幂等键：`POST` 创建类接口支持可选请求头 `Idempotency-Key`（管理端导入确认、学员端提交作答建议携带），服务端以 `idempotency:{key}` 去重（TTL 24h），重复请求返回首次结果。
- 错题更新（`wrong_question`）、面试结束落库（`interview_record`）使用乐观锁：两表均带 `version INT NOT NULL DEFAULT 0`（MyBatis-Plus `@Version`），更新条件为 `WHERE id = ? AND version = ?`，版本不匹配返回 10004，前端提示刷新后重试（评审 R-01 裁决：补字段；03 §4.3/§4.4 与 schema.sql 已同步）。
- 面试评分暂存：`interview:temp:{sessionId}`（题目快照含 referenceAnswer + 逐题得分，TTL 24h），`finish` 单事务读取后落库并删除。

## 4. 学员端接口明细

> 前缀 `/api/portal/v1`。除标注「公开」外，均需学员登录。

### 4.1 认证与账号（P-A01 ~ P-A12）

#### P-A01 发送短信验证码（公开）
- `POST /auth/sms-code`
- 参数：`{ mobile: string(11), type: "register"|"login"|"reset" }`
- 规则：① 60s 冷却、每日 ≤10 次（2.12）；② 验证码 6 位数字 TTL 5min（`sms:code:{type}:{mobile}`）；③ `type=register` 且已注册 → 20001；`type=reset` 且未注册 → 10003；`type=login` 不校验注册态。
- 响应：`{ code:0, data:{ expireSeconds:300 } }`
- 错误码：10000 / 10005(429) / 20001(409) / 20006(429)

#### P-A02 注册（公开）
- `POST /auth/register`
- 参数：`{ mobile, code, password }`（确认密码由前端本地校验，不入参）
- 规则：① 验证码校验（失败 20002，连续 5 次失效）；② 密码 **6~20 位**（需求 §3.2；强度条为前端展示，服务端只校长度与字符集）；③ 写入 `student`：`mobile`、`password_hash`（BCrypt）、`nickname` 默认「用户+手机号后 4 位」（DB 必填，无唯一约束，注册后可改）、`avatar` 置 NULL（未设置时前端显示 `system_setting.default_avatar`）、`status=1`、`gender=0`；④ 签发双令牌。
- 错误码：10000 / 20002 / 20001(409)

#### P-A03 密码登录（公开）
- `POST /auth/login/password`
- 参数：`{ account: 手机号或邮箱, password }`（需求 §3.2 登录字段为「手机号/邮箱」；**不支持昵称登录**——DB `nickname` 无唯一约束）
- 规则：① 邮箱匹配须唯一命中（`student.email` 由 `uk_student_email` 保障唯一，DB 层不会出现重复值；仍按「命中多条即失败」防御处理，避免枚举）；② 失败计数 `login:fail:{account}`，连续 5 次锁定 5min（20004）；③ 禁用账号 → 20005；④ 成功签发双令牌、更新 `last_login_at`、清空失败计数。
- 响应 `data`：`{ accessToken, refreshToken, student:{ id, nickname, avatar } }`（与 P-A10 已绑定分支同构）。
- 错误码：10000 / 20003 / 20004(423) / 20005(403) / 10005(429)

#### P-A04 验证码登录（公开）
- `POST /auth/login/sms`
- 参数：`{ mobile, code }`
- 规则：验证码校验 + 签发双令牌；连续 5 次校验失败该验证码失效。
- 错误码：10000 / 20002

#### P-A05 找回密码·验证验证码（公开）
- `POST /auth/reset/verify`
- 参数：`{ mobile, code }`
- 规则：校验通过发放一次性重置令牌 `reset:token:{token}`（TTL 10min），响应 `data:{ resetToken }`。
- 错误码：10000 / 20002 / 10003

#### P-A06 找回密码·重置（公开）
- `POST /auth/reset`
- 参数：`{ resetToken, newPassword }`
- 规则：令牌有效期内可重置密码，使用后令牌失效。
- 错误码：10000 / 10004 / 20004

#### P-A07 刷新令牌
- `POST /auth/refresh`（携带 `X-Refresh-Token`）
- 规则：旧 refreshToken 校验通过后轮换签发新双令牌，旧 token 立即失效（重放返回 10001）。
- 响应 `data`：`{ accessToken, refreshToken }`
- 错误码：10001(401)

#### P-A08 登出
- `POST /auth/logout`（携带 `X-Refresh-Token`）
- 规则：accessToken 的 jti 进黑名单（TTL 至过期）；refreshToken 失效；幂等（重复登出返回成功）。
- 响应 `data`：`null`

#### P-A09 第三方授权入口（公开）
- `GET /auth/oauth/{provider}/authorize`（`provider`：1 微信 / 2 QQ / 3 GitHub）
- 响应 `data`：`{ authorizeUrl, state }`
- 规则：生成一次性 `state` 写 Redis `oauth:state:{state}`（TTL 10min，值含 provider 与端标识）；按平台拼装授权 URL（微信开放平台扫码 / QQ 互联 / GitHub OAuth App）；前端整页跳转 `authorizeUrl`。平台 AppID/Secret 由应用配置项注入（`app.oauth.*`），不落库、不出现在响应中。
- 错误码：10000 / 20012(503，平台未配置或授权服务不可用)

#### P-A10 第三方授权回调（公开）
- `GET /auth/oauth/{provider}/callback?code=&state=`
- 规则：① `state` 一次性校验（不存在/已用/平台不符 → 20014）；② 用 `code` 换取第三方令牌并拉取用户信息（`open_id` / `union_id` / 昵称 / 头像），第三方令牌用完即弃、**不落库**；③ 命中 `student_oauth(provider, open_id)` 且学员 `status=1` → 直接签发双令牌（与 P-A03 同构）；④ 未命中 → 生成一次性绑定票据 `oauth:ticket:{ticket}`（TTL 10min，含 provider/open_id/union_id/昵称/头像），返回待绑定。
- 响应 `data`：已绑定 `{ needBind:false, accessToken, refreshToken, student:{ id, nickname, avatar } }`；待绑定 `{ needBind:true, ticket, providerNickname, providerAvatar }`
- 错误码：10000 / 20005(403 学员已禁用) / 20012 / 20014

#### P-P02 提交作答

- 参数：`{ answers:[{ questionId, answer, durationSeconds }] }`
- 规则：① 客观题服务端重判分（防伪造）；② 简答题触发 AI 批改（SSE 单独接口评分，本接口为最终落库），`score>=6` 判通过；AI 不可用时降级关键词判分并在响应标记 `degraded:true`；③ 写 `practice_record`（`question_id`/`mode`/`is_correct`/`duration_seconds`/`practiced_at`；**DB 无作答快照列**，作答内容不入库，仅错题经 `wrong_question.last_answer` 留痕）；④ 错题 upsert：答错新增/更新 `last_answer`、`error_count` 累加（D4-8），答对则 `corrected_count` 累加、连续 3 次答对置 `status=2`（已掌握）；⑤ **已掌握（`status=2`）的错题再次答错时回退为 `status=1`（待复习）并将 `corrected_count` 归零**（Q1 定稿）；⑥ 同一题重复作答不做跨练习拦截（前端本地进度控制，后端无唯一约束）。

### 4.7 AI 面试（P-I01 ~ P-I08）

#### P-I01 面试配置
- `GET /interview/config`

- 规则：`remainingCount` 来自 Redis 当日配额（2.12）。

#### P-I02 发起面试
- `POST /interview/sessions`
- 参数：`{ subjectId, difficulty, count }`
- 规则：① 校验并扣减当日配额（`interview:quota:{studentId}:{yyyymmdd}`，不足 20007）；② 出题：**面试题库** `interview_question`（`status=1 已上架`）按方向（`subject_id`）+难度抽取为主，不足部分由 AI 补生成快照题（D4-6）；③ 题目快照（含 `reference_answer`）+ 配置写 `interview:temp:{sessionId}`（TTL 24h），**不写数据库**（D4-4）；④ 返回会话号与题目（不含答案）；⑤ 返回题目 `source` 标记来源（`bank` 题库 / `ai` 快照题），用于报告中的 AI 覆盖率展示。
- 响应 `data`：`{ sessionId, questions:[{ order, subjectId, difficulty, content, source }], questionCount }`（`questionCount` 与请求 `count` 一致，落库至 `interview_record.question_count`）
- 错误码：10000 / 20007(429) / 20009

#### P-I03 逐题评分（SSE）
- `POST /interview/sessions/{id}/answers`
- 参数：`{ order: number, studentAnswer: string }`——**每答完一题调用一次**（与需求 3.8.2「每题提交后依次展示分析中 → 评分中 → 思考中 → 下一题」及 02 §2.3 时序图的逐题循环一致；作答内容同时由前端本地持久化，D16）
- 规则：对该题调用 AI 评分；事件流 `status(analyzing→grading→thinking)` → `token`（增量评语）→ `grade`（`{order, score, feedback, degraded, referencePoints}`，终止事件：服务端将本题得分与评语写入 Redis 暂存 `interview:temp:{sessionId}`（防伪造，D4-4），前端收到后关闭流并进入下一题）；会话不存在/已过期 → 20008。
- 错误码：10000 / 20008(404) / 20010(503，AI 不可用且无可降级)
- 返回类型：`text/event-stream`（2.9）

#### P-I04 结束面试
- `POST /interview/sessions/{id}/finish`
- 参数：`{ answers:[{ order, studentAnswer, durationSeconds }] }`（未作答题 score=0、studentAnswer=null，保证回放完整）
- 规则：① 读取 Redis 暂存逐题得分，单事务写入 `interview_record` + `interview_question_score`（question_id 可空=快照题，含 question_text 快照）+ `interview_report`（AI 生成 6 维评估）；② 删除 `interview:temp:{sessionId}`；③ 返回报告 id。
- 响应 `data`：`{ reportId, overallScore }`
- 错误码：10000 / 10003 / 20008 / 20010

#### P-I05 面试报告详情
- `GET /interview/reports/{id}`
- 响应 `data`：`{ overallScore, trendDelta(相比上次), dimensions:{...6 维雷达}, strengths:[], weaknesses:[], suggestions:[], improveCards:[3 张提升卡], questionReviews:[{ order, questionText, studentAnswer, score, feedback }], aiCoverage(快照题占比) }`
- 规则：`trendDelta` = 本次 `overall_score` − 该学员**同方向（`subject_id` 相同）时间上一条**面试记录的 `overall_score`；无同方向上一条则为 `null`，前端不展示趋势（Q5 定稿：回归需求 §3.8.3「同方向历史成绩」原文）。
- 错误码：10003

#### P-I06 重新生成报告
- `POST /interview/reports/{id}/regenerate`
- 规则：基于本次逐题得分重新调用 AI 生成报告（覆盖原报告，单事务更新）；消耗 AI 调用，失败 20010。
- 错误码：10003 / 20010

#### P-I07 面试记录

#### P-I08 面试统计

### 附录 D 题目状态流转矩阵（需求 §4.3.3）

```
新增 ──▶ 待审核 ──审核通过──▶ 已上架 ──下架──▶ 已下架
              │                 ▲                │
              │ 审核不通过      │                │ 重新上架
              ▼                 │                ▼
           已驳回 ──重新提交──▶ 待审核 ◀── 重新上架
```

| 当前 \ 操作 | 审核通过 | 审核不通过 | 上架 | 下架 | 重新提交 | 重新上架 |
|---|---|---|---|---|---|---|
| 待审核 | 已上架 | 已驳回 | ✗ | ✗ | ✗ | ✗ |
| 已上架 | ✗ | ✗ | ✗ | 已下架 | ✗ | ✗ |
| 已下架 | ✗ | ✗ | 待审核 | ✗ | ✗ | 待审核 |
| 已驳回 | ✗ | ✗ | ✗ | ✗ | 待审核 | ✗ |

> ① 非法流转返回 30006。
> ② **编辑后状态保持原状态**（Q2 定稿）：待审核/已驳回编辑后仍为待审核（重新走审核）；已上架编辑后仍为已上架（内容即时生效，运营可手动下架）；已下架编辑后保持已下架。
> ③ **驳回原因**（D4-9）：审核不通过时 `rejectReason` 必填写入 `question.reject_reason`（1~255 字符，超长 10000）；审核通过（任意状态→已上架）与 A-Q09 重新提交时清空该列。
> ④ `4 草稿` 为 DB 预留值，不在本矩阵内，接口与筛选均不使用（Q6 定稿）。
