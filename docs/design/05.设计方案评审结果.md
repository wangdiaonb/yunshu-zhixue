## 1. 评审范围与方法

### 1.1 评审方法

采用 **四向交叉比对**，任一方向不闭合即记为问题：

```
需求文档 ──→ 01 功能模块 ──→ 03 数据库（+ schema.sql）
    │              │                 │
    │              └──→ 04 API 接口 ←┘
    │                        │
    └──→ prototype 原型 ─────┘
                 ↑
     database-rules / api-rules / CLAUDE.md（规则约束层）
```

1. **功能完整性**：以需求文档 §3（学员端 8 节）、§4（管理端 12 小节）为基准逐项打勾，检查「是否有模块职责 → 是否有表 → 是否有接口」三段链条完整。
2. **架构合理性**：检查 02 的技术选型、13 个模块（M1~M13）职责、依赖方向、事务与缓存边界，以及 02 与 03/04 的决策引用是否自洽。
3. **数据与接口一致性**：逐表对照 04 的请求/响应字段与 03 列定义；核对 04 附录 A（权限码）、附录 B（错误码）、附录 C（枚举）与 03 §5、schema.sql 种子是否同源。
4. **规范符合性**：`database-rules.md` 4 章 13 条、`api-rules.md` 5 章 18 条逐条核对；重点验证「禁止物理外键」。
5. **自动化终检**：用脚本对 `schema.sql` 与 03/04 做机器比对（表数、索引名、权限 id 与编码、外键数、种子行数）。

## 4. 架构合理性检查

### 4.1 技术选型

| 项 | 选型 | 评审意见 |
|---|---|---|
| 形态 | 前后端分离、同域部署、单体分层 + 12 领域模块（模块化单体） | ✅ 与「单团队、单库、日活量级不大、需要快速迭代」匹配；无需微服务化，避免过度设计 |
| 后端 | Spring Boot 3 + MyBatis-Plus + MySQL 8 + Redis + MinIO | ✅ 未更换既定技术栈；MyBatis-Plus 逻辑删除插件与 03 §6 策略天然契合 |
| 前端 | Vue 3 + Vite（两端独立工程） | ✅ 两端独立部署与需求「两套账号、独立登录态」一致 |
| AI | Spring AI 抽象 + 可切换 provider + 规则降级 | ✅ 04 的 `degraded` 字段与 02 的降级策略闭环 |
| 实时 | SSE（仅 AI 批改、面试逐题评分） | ✅ 单向流场景用 SSE 而非 WebSocket，复杂度更低 |

### 4.2 模块职责与依赖

- 12 个领域模块（auth/system/student/subject/course/question/interviewbank/route/study/interview/stats/ai）+ 1 个 security 横切，职责单一、边界清晰。
- 依赖方向为「上层业务 → 下层基础」，**无环**：`interview → interviewbank + ai`、`study → question + route`、`route → course`、`question → subject`、`stats → study + interview + student`。
- Controller → Service → Mapper 三层约束与 04 的接口分组一一对应（每个 `/api/**` 前缀对应一个模块），不存在「接口无归属模块」。
- 事务边界（02 §2.5）与 04 的写操作口径一致：单次写单事务、面试结束单事务落库、AI 评分先 Redis 暂存再落库、日志异步落库。
