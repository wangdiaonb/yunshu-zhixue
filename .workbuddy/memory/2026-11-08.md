## 云枢智学 · 总体设计第三阶段：数据库设计（18:34，状态：待审核）

**产出**：`docs/design/03.数据库设计.md`（833 行）、`scripts/sql/schema.sql`（769 行，25 张表）。已创建 `scripts/sql/` 目录。

**依据**：`01.功能模块梳理.md`（16 项已闭环）、`02.整体架构设计.md`（D1~D21）、需求文档、`prototype/` MockData、`docs/rules/database-rules.md`。

**核心设计决策（供第四阶段 API 设计复用）**：
- 25 张表按 4 域：系统/账号 7、内容 11、学习训练 3、AI 面试 4。表名统一**单数**，主键 `id BIGINT UNSIGNED AUTO_INCREMENT`，**0 个物理外键**。
- 全表统一标准 5 字段：`id` / `created_at` / `updated_at`(`DATETIME(3)` UTC) / `deleted` / `deleted_at`。
- **R4 解法（🔧 建议，Q1 待确认）**：`deleted` 用「删除序号」语义（`0`=未删除，删除时写入本行 `id`），业务唯一索引统一为 `(业务键, deleted)` 联合唯一。解决「错题移除后再次答错会撞唯一键」的必现冲突；删除走自定义 `UPDATE ... SET deleted=id`，MP `@TableLogic` 只用于查询侧过滤。
- 时长统一存 `duration_minutes INT UNS`（不存原型 `'HH:MM'` 字符串）；分数用 `DECIMAL(4,1)`/`DECIMAL(5,2)`；错题等级由 `wrong_count` 派生不落库。
- 多值一律拆子表（选项/标签/关联/权限/能力维度）；仅 `interview_report` 的 4 个 AI 文本字段 + `operation_log.detail` 用「明确约定的 JSON」（database-rules 3.7 但书）。
- 统计全部由 `practice_record` / `interview_record` 明细聚合，本期不建预聚合表（架构 2.5 / R6）；配额、验证码、频控、导入预览、未完成面试会话一律 Redis 不落库。
- `question.status` 编码已由第一阶段定稿：1已上架 2已下架 3待审核 4草稿(预留不启用) 5已驳回，新增默认 3。
