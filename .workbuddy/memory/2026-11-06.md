## 云枢智学原型目录重构（学员端/管理端分层）

**背景**：`prototype/` 原本学员端 13 个 HTML 平铺在根目录，管理端在 `admin/`。按要求将所有学员端页面移入 `portal/`。

**最终结构**：
```
prototype/
├── map.html          # 原型地图（留在根目录）
├── portal/           # 学员端 13 页
├── admin/            # 管理端 12 页
├── assets/           # 两端共用 css/js
└── README.md
```

**关键改动（路径解析）**：
- `portal/*.html`：`assets/` → `../assets/`；`admin/login.html` → `../admin/login.html`
- `assets/js/portal.js`：新增 `IN_PORTAL` 常量 + `up()`（回根目录）+ `p(file)`（学员端内部页面）两个辅助函数，**所有**硬编码页面链接（NAV 数组、header 品牌、用户下拉、页脚、退出登录跳转）统一走 `p()`；指向 map/admin 的走 `up()`。
  - 原因：`portal.js` 是 portal 页和根目录 `map.html` 共用的外壳，同一份相对链接在两个层级下解析结果不同。
- `assets/js/core.js` `mountProtoFab()`：`isAdmin` 判断改为 `/(admin|portal)/` 命中即返回 `../map.html`。
- `assets/js/admin.js`：`../index.html` → `../portal/index.html`。
- `assets/js/map.js`：学员端条目 path 加 `portal/` 前缀；重置后跳转 `portal/index.html`。
- `admin/login.html`：`../index.html` → `../portal/index.html`，`../login.html` → `../portal/login.html`。
- `map.html`：进入学员端按钮 → `portal/index.html`。

**验证方式（可复用）**：python http.server + Chrome headless `--dump-dom`，配合一个临时 `_t.html` 写入 `ys_admin` 的 localStorage 再 `location.replace` 到后台页，即可在无会话情况下渲染后台并检查生成后的 DOM 链接。注意用 bash 工具时**服务端与测试必须在同一条命令内**（命令结束进程树被回收）。

## 原型架构要点（阅读结论，供后续开发参考）
- `data.js` 是只读种子（8 学科 26 阶段 / 81 题 / 课程·路线·面试题·学员·用户·角色·日志），`DB.get()` 惰性 clone 进 `ys_db_*`。
- **前后台数据源不统一**：学员端 `bank.js / route.js / interview.js` 直接读 `DATA.*` 静态常量，管理端读 `DB.get()`；后台改题不会反映到前台。真做后端时这是第一个要打通的点。
- 权限：6 组 25 项，`can()` + `[data-perm]` + `applyPerms()` 删除节点；角色预览靠写 `adminRolePreview` 后整页 reload。
- 登录态两套：`ys_user`（学员，默认注入 demoUser 即打开即登录）/ `ys_admin`（后台，各页 boot 无则 replace 到 login.html）。
